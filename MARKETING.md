# Tundra Frontmatter Wrangler — Marketing

Version: 3.5.3

## Product positioning

**Clean up frontmatter across your vault with a preview before every write.**

Tundra turns repeated YAML edits into a six-step workflow: select notes, inspect the inventory, configure an operation, review the diffs, apply safely, and inspect or roll back the result.

## For

Obsidian users who maintain consistent properties and tags across many Markdown notes, but want to inspect changes and preserve later edits before applying a bulk update.

## Key reasons to choose Tundra

- Rename properties, manage tags, reorder schema, or clean supported YAML formatting across a selected set of notes.
- Resolve key collisions explicitly and inspect each note's proposed diff.
- Skip malformed or unsupported frontmatter instead of silently rewriting it.
- Detect stale previews, journal exact originals, and restore a batch only when the note still matches the batch output.
- Use optional AI proposals for top-level properties while keeping the same review and apply safeguards.
- Keep deterministic operations local; connect to billing only for account/credit tasks.

## Short description

Reviewed bulk frontmatter editing for Obsidian, with explicit previews, guarded writes, and a recoverable recent-batch journal.

## Claims and limitations

Tundra works on top-level properties; it does not promise a general YAML editor or nested-schema transformer. AI suggestions require the user's own OpenRouter key and confirmation, may incur OpenRouter charges, and are never applied without the ordinary per-note review. Rollback is guarded and may skip notes that have changed since the batch.
